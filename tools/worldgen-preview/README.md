# Local world generator preview

Run from the repository root:

```sh
node tools/worldgen-preview/dev.mjs
```

Open <http://127.0.0.1:4173>. The watcher rebuilds the `worldgen` crate's preview example when Rust sources (including terrain features), feature RON definitions, biome repository and map RON files, its manifest, or the example change. The frontend stays available during builds. The previous generator remains available if compilation fails. The browser polls the build ID and refreshes its cache after a successful restart, keeping previous images as placeholders. Restart the dev runner after editing `dev.mjs` itself. After protocol changes, refresh the browser so it loads the matching frontend modules.

The HTTP adapter is `crates/worldgen/examples/worldgen_preview.rs`. It imports the same `worldgen` library used by the server, without building Bevy or the game server. Frequency is a preview adapter control; elevation is evaluated at frequency-scaled global coordinates. Tile colors come from the palette entry selected by the generator from final height and temperature after biome classification (`#RGB` or `#RRGGBB`) and are decoded in browser workers without biome-specific color logic. Hover a tile to inspect normalized height and daily average Celsius temperature. Unclassified tiles use the legend's neutral color and retain their height and temperature.

The sidebar adjusts average-temperature coefficients, orbital phase, axial tilt, crater sizes and density, impact basins, and both fBm noise sources (frequency, octaves, lacunarity, persistence, and independent optional seed overrides). Blank seed overrides follow the world seed, with a separate derived seed for temperature regions. Terrain coordinate scale multiplies elevation noise frequency; regional noise is sampled directly in global tile coordinates. Defaults and validation limits come from Rust metadata. Changes regenerate the visible map and are stored in the URL; Reset settings restores the current generator defaults.

Choose a **Default biome map** from the RON files in `crates/worldgen/src/biomes/maps` (default: `default.ron`). All maps reference the single biome repository in `src/biomes/biomes.ron`, which stores names and appearance palettes. Biome selection ranges live in map files; appearance selection ranges live on palette entries. Palettes are optional. Entries provide preview colors; `surface_biome` and `palette_index` can later identify game textures. `biome` independently identifies the territory. The **Height × temperature** chart's **View map** selector displays either the selected default map or a feature map from `src/features/{basin,crater,volcano}.ron`. Each block displays the actual height-temperature palette regions clipped to the biome rule. Palette rules use first-match order, with entry 0 as the fallback when none matches. Palette-free territory maps are shown in neutral gray and labeled “terrain appearance”. Hover or focus a block for the referenced biome’s name, palette size, and exact ranges. The legend shows a swatch for every palette entry, and tile tooltips show the selected entry number and color. The terrain key and tile tooltips use the shared repository, including feature biomes. Selecting a different default map preserves terrain metrics and is saved as `biome` in the URL. Range upper bounds are exclusive except height 1, which belongs to rules ending at 1. Overlapping rules use the first match. A gap in the last feature territory’s map falls back to the default map; only the biome stage classifies tiles after all terrain and temperature changes.

Feature maps identify territory independently of appearance. Craters and basins have no owned palettes: they are visible through height deformations and default terrain classification, and tile inspection still identifies their biome. Volcanic biomes own palettes that activate only when final height exceeds the pre-feature terrain by their `palette_height_threshold` (currently 0.01). This gate belongs to the biome definition and never hides the territory marker. No biome objects are implemented.

The **Map mode** selector at the top of the map switches between **Biomes**, **Temperature**, and **Height**. Temperature uses a fixed blue-to-red scale from −50 to 50 °C, with 0 °C in the middle; values outside the scale use its end colors. Height uses grayscale from black at 0 to white at 1. Each metric view shows its scale and includes tiles with no matching biome. Hover still reports exact temperature and height. Modes reuse cached samples and switch without regenerating terrain, keep the current view, and are saved in the URL as `mode=biomes`, `mode=temperature`, or `mode=height`.

Temperature always uses the daily average for the selected season. Orbital phase 0 / 0.5 represents equinox, 0.25 northern summer, and 0.75 northern winter. Features modify height before temperature and biome classification. Each feature group exposes **Peak temperature offset (°C)** (`crater_temperature_offset`, `basin_temperature_offset`, and `volcano_temperature_offset`), with defaults from the feature RON files. Values may be positive or negative and are included in shared URLs and Reset settings; weighted offsets accumulate and are added to climate temperature before biome selection. Density 0 disables craters; density 4 generates four per cell. Minimum radius must not exceed maximum radius, and maximum radius × 1.5 must fit within a generation cell.

The **Impact basins** section adjusts cell size, probability, minimum/maximum radius, depth and rim height, interior smoothing, and smoothing octave count. Basins run before craters, temperature, and biome classification. Their smoothing source uses the current elevation seed, frequency, lacunarity, persistence, and terrain coordinate scale; its octave count is capped to the elevation octave count. Probability 0 disables basins, while 1 places one in every generation cell. Use **Fit world (□)** or zoom out to see these large features; the default probability 0.2 keeps them uncommon. Minimum values must not exceed maximums, and maximum radius × 1.5 must fit within the basin cell size. Basin controls are also saved in the URL and restored by Reset settings.

The **Volcanoes** section controls cell size, probability, minimum/maximum cone radius and height, caldera radius as a fraction of cone radius, and caldera depth. Volcanoes build raised cones with summit depressions after basins and craters; their height feeds temperature and biome classification. Volcano territory is always marked. Its biome decides whether to use the volcanic palette or inherit terrain appearance by comparing final height with the pre-feature environment. Probability 0 disables them, and 1 places one in every cell. Caldera radius 0 produces solid cones. Heights and depths use normalized height units. Maximum radius must fit within cell size, and minimum radius/height must not exceed their maximums. Controls use the `volcano_` API and URL prefix and support Reset settings. Use **Fit world (□)** to find sparse volcanoes; zoom in to see their calderas.

Panning, drawing, and requests stay within the world dimensions reported by the generator. Zooming out stops at a full-world view; the square button also fits the world. At LOD 0, cells represent exact samples. Below one pixel per tile, each cell samples a representative tile from a larger region; the tooltip identifies that tile and LOD.

The preview API is versioned by `protocol: 5` in `/api/meta?size=32`, alongside `biomes` (the shared repository with per-biome palettes), `biome_rules` (the selected default map), `feature_biome_maps` (feature rules joined with appearance palettes), `build`, `world: {width, height}` in tiles, and `controls` describing the parameter keys, labels, groups, defaults, limits, and input steps. `/api/region` takes `min_x`, `min_y`, `max_x`, `max_y` (inclusive chunk addresses), `lod`, and any parameter keys from `controls`; omitted settings use Rust defaults. Noise keys use `elevation_` / `region_` prefixes; temperature keys use `temperature_`. Planet keys are `orbit` and `axial_tilt`. Crater keys are `crater_cell_size`, `crater_min_radius`, `crater_max_radius`, and `crater_density`. Basin controls use the `basin_` prefix, including `basin_probability`, `basin_smoothing`, and `basin_coarse_octaves`. The adapter uses `WorldGenerator::draft_at` to obtain height, daily-average temperature, and biome. Each row-major sample is 18 bytes: status u8 (0 unclassified, 1 colored, 2 territory without appearance, 255 outside-world padding), RGB u8[3], normalized height f32 little-endian, Celsius temperature f32 little-endian, territory biome ID u16 little-endian, surface biome ID u16 little-endian, and palette index u16 little-endian. Territory IDs are valid for status 1 or 2; surface IDs and palette indices are valid for status 1. Both biome IDs index the shared repository. Tooltips show the territory name and the actual surface supplying its palette. Padding carries NaN metrics. Out-of-world chunks and invalid parameters are rejected. The frontend can use another implementation of this contract through its `?api=...` base URL (cross-origin providers must allow CORS).

To run a second preview without stopping an existing one:

```sh
node tools/worldgen-preview/dev.mjs --port 4183 --api-port 4184
```
