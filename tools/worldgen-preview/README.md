# Local world generator preview

Run from the repository root:

```sh
node tools/worldgen-preview/dev.mjs
```

Open <http://127.0.0.1:4173>. The watcher rebuilds the `worldgen` crate's preview example when Rust sources (including terrain features), feature RON definitions, biome repository and map RON files, tile palette and mapping files, object definitions and placement rules, its manifest, or the example change. The frontend stays available during builds. The previous generator remains available if compilation fails. The browser polls the build ID and refreshes its cache after a successful restart, keeping previous images as placeholders. Restart the dev runner after editing `dev.mjs` itself. After protocol changes, refresh the browser so it loads the matching frontend modules.

The HTTP adapter is `crates/worldgen/examples/worldgen_preview.rs`. It imports the same `worldgen` library used by the server, without building Bevy or the game server. Frequency is a preview adapter control; elevation is evaluated at frequency-scaled global coordinates. Tile colors come from the global tile selected by `TileMapper` from completed height, temperature, and biome after all generator stages (`#RGB` or `#RRGGBB`) and are decoded in browser workers without biome-specific color logic. Hover a tile to inspect normalized height and daily average Celsius temperature. Unclassified tiles use the legend's neutral color and retain their height and temperature.

The sidebar adjusts average-temperature coefficients, orbital phase, axial tilt, crater sizes and density, impact basins, and both fBm noise sources (frequency, octaves, lacunarity, persistence, and independent optional seed overrides). Blank seed overrides follow the world seed, with a separate derived seed for temperature regions. Terrain coordinate scale multiplies elevation noise frequency; regional noise is sampled directly in global tile coordinates. Defaults and validation limits come from Rust metadata. Changes regenerate the visible map and are stored in the URL; Reset settings restores the current generator defaults.

Choose a **Default biome map** from `crates/worldgen/src/biomes/maps` (default: `default.ron`). Maps reference biome names in `src/biomes/biomes.ron`, which contains no appearance data. Classification rules use final height and temperature, with feature maps taking precedence and gaps falling back to the selected default map. Selecting another map preserves terrain metrics and is saved as `biome` in the URL.

Appearance is stored separately: `src/tiles/palette.ron` is a flat global palette, and `src/tiles/map.ron` maps completed `TileData { height, temperature, biome }` to a global tile ID. Tile rules use first-match order, optional biome filters, and height-temperature ranges. Missing biome filters match every biome. Gaps return no tile. All ranges have exclusive upper bounds except height 1, which belongs to rules ending at 1. Crater and basin territories use climate fallback tiles. Volcanic territories use biome-specific rules with final height and temperature; the old pre-feature uplift gate has been removed.

The **Height × temperature** chart's **View map** selector displays the default or a feature biome map. Its colors come from independent tile rules intersected with the biome classification regions. Hover or focus a region for biome, global tile ID, and ranges. The legend lists global palette tiles; tile tooltips report biome identity separately from the selected tile ID, name, and color. The **Objects** toggle shows generated rocks, large rocks, iron ore, and trees over the terrain. The key shows each type and its occupied footprint. Objects draw at close zoom levels (at least 4 pixels per tile); zooming out pauses object requests. Hover any occupied tile to highlight the complete footprint and inspect the object type, anchor, dimensions, and instance ID. The toggle is saved in shared URLs as `objects=0` when disabled. Objects remain available in all three map modes.

The **Map mode** selector at the top of the map switches between **Biomes**, **Temperature**, and **Height**. Temperature uses a fixed blue-to-red scale from −50 to 50 °C, with 0 °C in the middle; values outside the scale use its end colors. Height uses grayscale from black at 0 to white at 1. Each metric view shows its scale and includes tiles with no matching biome. Hover still reports exact temperature and height. Modes reuse cached samples and switch without regenerating terrain, keep the current view, and are saved in the URL as `mode=biomes`, `mode=temperature`, or `mode=height`.

Temperature always uses the daily average for the selected season. Orbital phase 0 / 0.5 represents equinox, 0.25 northern summer, and 0.75 northern winter. Features modify height before temperature and biome classification. Each feature group exposes **Peak temperature offset (°C)** (`crater_temperature_offset`, `basin_temperature_offset`, and `volcano_temperature_offset`), with defaults from the feature RON files. Values may be positive or negative and are included in shared URLs and Reset settings; weighted offsets accumulate and are added to climate temperature before biome selection. Density 0 disables craters; density 4 generates four per cell. Minimum radius must not exceed maximum radius, and maximum radius × 1.5 must fit within a generation cell.

The **Impact basins** section adjusts cell size, probability, minimum/maximum radius, depth and rim height, interior smoothing, and smoothing octave count. Basins run before craters, temperature, and biome classification. Their smoothing source uses the current elevation seed, frequency, lacunarity, persistence, and terrain coordinate scale; its octave count is capped to the elevation octave count. Probability 0 disables basins, while 1 places one in every generation cell. Use **Fit world (□)** or zoom out to see these large features; the default probability 0.2 keeps them uncommon. Minimum values must not exceed maximums, and maximum radius × 1.5 must fit within the basin cell size. Basin controls are also saved in the URL and restored by Reset settings.

The **Volcanoes** section controls cell size, probability, minimum/maximum cone radius and height, caldera radius as a fraction of cone radius, and caldera depth. Volcanoes build raised cones with summit depressions after basins and craters; their height feeds temperature and biome classification. Volcano territory is always marked. The final tile mapper selects its appearance from final height, temperature and biome. Probability 0 disables them, and 1 places one in every cell. Caldera radius 0 produces solid cones. Heights and depths use normalized height units. Maximum radius must fit within cell size, and minimum radius/height must not exceed their maximums. Controls use the `volcano_` API and URL prefix and support Reset settings. Use **Fit world (□)** to find sparse volcanoes; zoom in to see their calderas.

Panning, drawing, and requests stay within the world dimensions reported by the generator. Zooming out stops at a full-world view; the square button also fits the world. At LOD 0, cells represent exact samples. Below one pixel per tile, each cell samples a representative tile from a larger region; the tooltip identifies that tile and LOD.

The preview API uses `protocol: 6` in `/api/meta?size=32`. Metadata includes `biomes` (identity only), `biome_rules`, `feature_biome_maps`, `tile_palette` (flat appearance entries), `tile_rules` (resolved global tile IDs, optional biome IDs, height and temperature ranges), and `object_types` (object names and footprints), plus `build`, `world: {width, height}` in tiles, and `controls`. `/api/region` takes inclusive chunk addresses `min_x`, `min_y`, `max_x`, `max_y`, `lod`, and any keys from `controls`; omitted settings use Rust defaults. Noise keys use `elevation_` / `region_` prefixes, temperature uses `temperature_`, planet keys are `orbit` and `axial_tilt`, and features use `crater_`, `basin_`, and `volcano_`. The adapter runs generator stages, then passes completed terrain data to the separate mapper. Each row-major sample is 16 bytes: status u8 (0 unclassified, 1 mapped tile, 2 biome without a tile, 255 outside-world padding), RGB u8[3], normalized height f32 LE, Celsius temperature f32 LE, biome ID u16 LE, and global tile ID u16 LE. Biome IDs are valid for status 1 or 2; tile IDs are valid for status 1. Padding carries NaN metrics. Invalid parameters and out-of-world chunks are rejected. The frontend accepts another implementation through `?api=...` (cross-origin providers must allow CORS).

`/api/chunk?x=250&y=250&size=32&seed=42` returns one complete chunk as JSON using the same generation settings as `/api/region`. The response contains `position`, `size`, row-major `tiles` (global tile IDs), and `objects`. Each object contains `kind` (object repository ID), `footprint`, and `id: { rule_id, anchor: {x, y} }`. Coordinates are global. Objects touching more than one chunk appear in each response with the same instance ID; consumers deduplicate those IDs. Invalid chunk coordinates and missing terrain/tile classifications return HTTP 400. Requests run on the existing HTTP worker pool with a bounded input queue. The frontend loads these chunks separately from terrain samples, keeps at most four object requests active, and deduplicates crossing objects by instance ID before drawing. Settings, biome-map changes, and generator rebuilds clear object data and cancel outdated requests. Edit `crates/worldgen/src/objects/{objects,placement}.ron` to tune footprints, density, and terrain restrictions; the dev runner rebuilds on changes. Symbols are drawn in canvas code and new object types receive a generic marker until a dedicated symbol is added.

To run a second preview without stopping an existing one:

```sh
node tools/worldgen-preview/dev.mjs --port 4183 --api-port 4184
```
