# Local world generator preview

Run from the repository root:

```sh
node tools/worldgen-preview/dev.mjs
```

Open <http://127.0.0.1:4173>. The watcher rebuilds the `worldgen` crate's preview example when the worldgen Rust sources, any file in `crates/worldgen/config/`, its manifest, or the example change. The frontend stays available during builds. The previous generator remains available if compilation fails. The browser polls the build ID and refreshes its cache after a successful restart, keeping previous images as placeholders. Restart the dev runner after editing `dev.mjs` itself. After protocol changes, refresh the browser so it loads the matching frontend modules.

The HTTP adapter is `crates/worldgen/examples/worldgen_preview.rs`. It imports the same `worldgen` library used by the server, without building Bevy or the game server. Frequency is a preview adapter control; elevation is evaluated at frequency-scaled global coordinates. Samples carry completed height, temperature, biome, and ground biome after all generator stages; all appearance is resolved in the browser from the client presentation being edited. Hover a tile to inspect normalized height, daily average Celsius temperature, its texture and overlay layer, and the ground biome under feature biomes. Unclassified tiles use the legend's neutral color and retain their height and temperature.

The sidebar adjusts average-temperature coefficients, orbital phase, axial tilt, crater sizes and density, impact basins, and both fBm noise sources (frequency, octaves, lacunarity, persistence, and independent optional seed overrides). Blank seed overrides follow the world seed, with a separate derived seed for temperature regions. Terrain coordinate scale multiplies elevation noise frequency; regional noise is sampled directly in global tile coordinates. Defaults and validation limits come from Rust metadata. Changes regenerate the visible map and are stored in the URL; Reset settings restores the current generator defaults.

The **Biome preset** selector (saved as `biome` in the URL) picks the worldgen config: `default.ron` is the bundled `crates/worldgen/config/` and `old.ron` the previous default, kept in `crates/worldgen/config/presets/old/` (an override folder, also usable by the server through `WORLDGEN_CONFIG`). A preset supplies biomes, the terrain and feature biome maps, and objects; the sidebar controls set the numeric settings for either. The default preset has five climate kinds with five height variants each (`<kind>_floor|low|mid|upland|ridge`): snow below −16 °C, frost to −6 °C, plain to 6 °C and desert above; sulfur and basalt appear only in impact basins, which come in two types (`variants` in `features/basins.ron`: basalt and sulfur, picked per basin by weight) with irregular outlines (`shape_noise`, the **Outline irregularity** control; 0 keeps circles) and apply in any climate warmer than frost; craters keep the surrounding climate and volcanoes are off. The Client presentation panel edits the matching client files: `crates/client/assets/world/` for the default, `crates/client/assets/world/presets/old/` for the old preset, each with its own draft. **Reset tints to palette** restores the default preset's palette (lower ground darker, so craters read as dark bowls).

## Client presentation

Appearance belongs to the game client, not to worldgen. The **Client presentation** panel edits a copy of the client's `crates/client/assets/world/tiles.ron` and `objects.ron` (plus the texture files in `crates/client/assets/textures/{tiles,objects}/`), and the textured map draws exactly what the client draws from them: the renderer in `dist/terrain.mjs` is a port of the client shader `crates/client/src/world/presentation/terrain.wgsl`, and `dist/presentation.mjs` mirrors the client's name resolution (`config.rs`, `catalog.rs`). Keep them in sync when changing either side. Edits are kept in browser storage as a draft; **Reload client files** discards them.

Workflow: tune the look, press **Save client files**, and copy the contents of `tools/worldgen-preview/export/assets/` into `crates/client/assets/` (the export folder is replaced on every save and ignored by git). The export contains `world/tiles.ron`, `world/objects.ron`, and a PNG for every texture that has a source.

The look follows two rules. **Height** is drawn with overlay layers: where textures on different layers meet, the higher one overlays the lower one with a crisp, slightly noisy edge, and the lower ground at its foot is shaded for a few pixels (ambient occlusion), so steps read as height. **Biomes** within a layer meet on crisp, irregular edges too (the biome covering a pixel most, plus a noise field of its own, wins; no shading), so the map reads as terraces. **Temperature** is drawn with tints: textures are neutral and shared per height band, and the ground is multiplied by its biome's tint. With tint smoothing radius 0 (the default) each biome is one flat color; a larger radius averages tints over neighboring tiles of the same height layer, softening colors inside a biome. Tints never bleed across a step. Default tints come from one muted temperature ramp (snow white, frost blue-gray, gray, warm gray, tan, ochre, copper, rust) at each biome's temperature midpoint, slightly lighter for higher bands; **Tints from temperature ramp** reapplies it.

- **Tile blending** (`blend` in `tiles.ron`): texture pixels per tile (textures repeat in world space; a 32 px texture spans 2 × 2 tiles at 16), overlay reach, edge noise for height and biome edges and its scale, height shadow strength and width (pixels), shadow scales for the south and north sides of a step (the south side, where the higher ground lies north of the lower ground, is shaded more by default: 1.5 vs 0.4; east and west sides interpolate), and tint smoothing radius (tiles).
- **Tile textures**: one row per texture the world uses: placeholder color, overlay layer (`layers` in `tiles.ron`), source, and bake tint. Default textures are height bands named `<surface>_<layer>` (`regolith_1..5`, `frost_1..4`, `basalt_*`): the layer is the biome's height rank within its temperature column of the biome map (+1), so higher ground overlays lower ground and temperature neighbors at the same rank share a texture; volcano biomes sit above all terrain. Lower regolith bands use rockier sheet art; frost turns from ice to snow with height. Sources are a client file, a region of the sprite sheet `crates/worldgen/examples/textures.png` (baked: `tint` recolors the art's luminance with the placeholder color, `blend` shifts its colors by the strength), or the flat placeholder color. Keep textures neutral; tints color them. As in the client, all tile textures must share one size; mismatched ones fall back to their placeholder with a warning.
- **Biomes: tint and texture** (`tints` and `textures` in `tiles.ron`): each biome's tint color and texture. A blank texture uses the biome's own name; several biomes may share one; `ground` draws the terrain biome underneath (used by crater and basin biomes, which only change objects, and take the ground's tint too). A `tiles.ron` without `tints` (the older per-biome colored format) is converted on load: its colors become tints.
- **Object textures**: drawn stretched over the footprint, or as a 90 % rectangle in the placeholder color, as in the client. Sheet sprites are baked at footprint × pixels per tile, standing on the bottom edge.

Pebbles are ordinary worldgen objects (`pebbles` in `crates/worldgen/config/objects.ron`, spawned by the `pebbles` set on unfrozen ground below height 0.8), not a ground overlay.

The map is drawn with +Y up, like the client.

The **Height × temperature** chart's **View map** selector displays the default or a feature biome map. Regions are colored with each biome's texture color (biomes drawn as their ground are gray). Hover or focus a region for its biome and ranges. The **Objects** toggle shows generated objects (rocks, large rocks, iron ore, trees, pebbles) over the terrain, drawn like the client draws them. The key shows each type and its occupied footprint. Objects draw at close zoom levels (at least 4 pixels per tile); zooming out pauses object requests. Hover any occupied tile to highlight the complete footprint and inspect the object type, anchor, dimensions, and instance ID. The toggle is saved in shared URLs as `objects=0` when disabled. Objects remain available in all three map modes.

**Textures** (on by default, saved as `textures=0` when disabled) draw the Biomes view with the client renderer once the map shows at least 4 pixels per tile. Chunk images are composed in browser workers at the texture resolution (capped at 1024 px per chunk) with a one-tile border from neighboring chunks (tints are smoothed over the neighbors first), as in the client, and recompose when a neighbor arrives or the presentation changes. Objects show at the same zoom.

The **Display** section holds view-only coefficients for the flat Biomes view (zoomed out or Textures off); neither the generator nor the client uses them. Flat colors are each texture's average color times the biome tint. **Height tint** (default 3, range 0–10, URL `height_tint`) multiplies colors by `1 + k × (height − 0.65)` (clamped to 0.25–1.75), so crater and basin bowls appear as dark discs with brighter rims; 0 disables it. **Relief shading** (default 1, range 0–5, URL `relief`) lights slopes from the north-west, measured per tile at every LOD. Changing either re-colors cached samples without regenerating terrain. **Reset display** restores the defaults.

The **Map mode** selector at the top of the map switches between **Biomes**, **Temperature**, and **Height**. Temperature uses a fixed blue-to-red scale from −50 to 50 °C, with 0 °C in the middle; values outside the scale use its end colors. Height uses grayscale from black at 0 to white at 1. Each metric view shows its scale and includes tiles with no matching biome. Hover still reports exact temperature and height. Modes reuse cached samples and switch without regenerating terrain, keep the current view, and are saved in the URL as `mode=biomes`, `mode=temperature`, or `mode=height`.

Temperature always uses the daily average for the selected season. Orbital phase 0 / 0.5 represents equinox, 0.25 northern summer, and 0.75 northern winter. Features modify height before temperature and biome classification. Each feature group exposes **Peak temperature offset (°C)** (`crater_temperature_offset`, `basin_temperature_offset`, and `volcano_temperature_offset`), with defaults from the feature RON files. Values may be positive or negative and are included in shared URLs and Reset settings; weighted offsets accumulate and are added to climate temperature before biome selection. Density 0 disables craters; density 4 generates four per cell. Minimum radius must not exceed maximum radius, and maximum radius × 1.5 must fit within a generation cell.

The **Impact basins** section adjusts cell size, probability, minimum/maximum radius, depth and rim height, interior smoothing, and smoothing octave count. Basins run before craters, temperature, and biome classification. Their smoothing source uses the current elevation seed, frequency, lacunarity, persistence, and terrain coordinate scale; its octave count is capped to the elevation octave count. Probability 0 disables basins, while 1 places one in every generation cell. Use **Fit world (□)** or zoom out to see these large features; the default probability 0.2 keeps them uncommon. Minimum values must not exceed maximums, and maximum radius × 1.5 must fit within the basin cell size. Basin controls are also saved in the URL and restored by Reset settings.

The **Volcanoes** section controls cell size, probability, minimum/maximum cone radius and height, caldera radius as a fraction of cone radius, and caldera depth. Volcanoes build raised cones with summit depressions after basins and craters; their height feeds temperature and biome classification. Volcano territory is always marked. The final tile mapper selects its appearance from final height, temperature and biome. Probability 0 disables them, and 1 places one in every cell. Caldera radius 0 produces solid cones. Heights and depths use normalized height units. Maximum radius must fit within cell size, and minimum radius/height must not exceed their maximums. Controls use the `volcano_` API and URL prefix and support Reset settings. Use **Fit world (□)** to find sparse volcanoes; zoom in to see their calderas.

Panning, drawing, and requests stay within the world dimensions reported by the generator. Zooming out stops at a full-world view; the square button also fits the world. At LOD 0, cells represent exact samples. Below one pixel per tile, each cell samples a representative tile from a larger region; the tooltip identifies that tile and LOD.

The preview API uses `protocol: 7` in `/api/meta?size=32`. Metadata includes `biomes` (identity only), `biome_rules`, `feature_biome_maps`, and `object_types` (object names and footprints), plus `build`, `world: {width, height}` in tiles, and `controls`. `/api/region` takes inclusive chunk addresses `min_x`, `min_y`, `max_x`, `max_y`, `lod`, and any keys from `controls`; omitted settings use Rust defaults. Noise keys use `elevation_` / `region_` prefixes, temperature uses `temperature_`, planet keys are `orbit` and `axial_tilt`, and features use `crater_`, `basin_`, and `volcano_`. Each row-major sample is 16 bytes: status u8 (0 unclassified, 1 classified, 255 outside-world padding), 3 reserved bytes, normalized height f32 LE, Celsius temperature f32 LE, biome ID u16 LE, and ground biome ID u16 LE (the terrain biome under a feature biome; equal to the biome elsewhere). Padding carries NaN metrics. Invalid parameters and out-of-world chunks are rejected. The frontend accepts another implementation through `?api=...` (cross-origin providers must allow CORS). The dev runner also serves `/client-assets/...` (the client's presentation files, read-only) and accepts `POST /export`.

`/api/chunk?x=250&y=250&size=32&seed=42` returns one complete chunk as JSON using the same generation settings as `/api/region`. The response contains `position`, `size`, row-major `tiles` (`{ biome, height }` samples, height quantized to u16), and `objects`. Each object contains `kind` (object repository ID), `footprint`, and `id: { rule_id, anchor: {x, y} }`. Coordinates are global. Objects touching more than one chunk appear in each response with the same instance ID; consumers deduplicate those IDs. Invalid chunk coordinates and missing terrain/tile classifications return HTTP 400. Requests run on the existing HTTP worker pool with a bounded input queue. The frontend loads these chunks separately from terrain samples, keeps at most four object requests active, and deduplicates crossing objects by instance ID before drawing. Settings, biome-map changes, and generator rebuilds clear object data and cancel outdated requests. Edit `crates/worldgen/config/objects.ron` (kinds, footprints, shared sets) and `crates/worldgen/config/biomes.ron` (per-biome spawns, density, terrain restrictions); the dev runner rebuilds on changes. New object types appear in the Object textures list with a placeholder color.

```sh
node tools/worldgen-preview/dev.mjs --port 4183 --api-port 4184
```
